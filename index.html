01 / CONTEXT

为什么做 EK STUDIO

面向中小电商卖家的 AI 商品视觉创作工具，把零散的需求沟通、图片生成和版本管理收进一个可继续推进的工作流。

01

参考图到场景图断层

卖家有商品实拍图，却不知道怎么描述想要的场景。传统做法是反复外包沟通，周期长、成本高。

02

多轮反馈没有统一入口

用通用对话工具生成图片时，修改意见散落在聊天记录里，无法回溯每一版的改动原因。

03

生成结果难以沉淀复用

没有统一的生成历史，卖家无法回看、对比、下载历史版本，每次都要从头开始。

02 / MY ROLE

我的角色

从需求洞察到可运行 Demo，独立负责 EK STUDIO 的产品方案、界面交互与本地落地。

独立开发者 / 产品方案负责人

这个项目从 0 到 1 由我一个人推进：先通过小红书、淘宝卖家访谈和自身电商观察定位痛点，再把它翻译成可演示的产品方案，最后用 Next.js + AI 图像模型做出本地可运行的 Demo。

过程中反复在"卖家能听懂"和"技术可实现"之间找平衡，目标是让打开网页的人都能理解：这个工具解决什么问题、为什么值得做、我做了什么。

03 / ARCHITECTURE

把创作流程拆成可继续推进的模块

顾问负责把想法说清楚，生成模块负责把画面做出来，历程看板负责让每一次尝试都可以被回看和继续。

DISCOVERY → GENERATION → ITERATION → ARCHIVE
01

AI 电商顾问

把模糊的出图想法梳理成结构化需求简报，不教用户卖货，只帮用户说清楚想要什么。

02

商品生成图

文字需求 + 1-4 张商品参考图，生成保持主体颜色与结构的电商场景图。

03

自由 AI 创图

纯文字创意生成，用于探索视觉方向，不依赖参考图也能快速产出概念。

04

历程看板

每次生成自动归档，支持模块筛选、搜索、批量下载和单轮删除清理。

05

登录 / 个人空间

本地演示账号 + JWT Cookie 会话，未来可扩展为跨设备的个人创作空间。

04 / TECH STACK

技术架构

用现代前端技术栈做界面，用 SQLite 做本地持久化，用 Provider 模式隔离不同 AI 模型接口。

层级 技术选型 选型理由
前端框架 Next.js 14 + React + TypeScript 类型安全、服务端路由、适合快速迭代个人项目
样式方案 Tailwind CSS + shadcn/ui 原子化样式保证一致性，组件库加速交互开发
后端接口 Next.js Route Handlers 无需额外后端服务，降低部署与演示成本
数据持久化 SQLite + better-sqlite3 本地文件型数据库，Demo 可离线运行，便于归档历程
会话认证 JWT Cookie 本地演示账号即可体验登录态，未来可扩展多用户
图像模型 DashScope（阿里云百炼）+ Provider 适配层 抽象模型调用层，方便切换不同图像生成服务

08 / CRAFT

藏在细节里的体验

工作台不是功能的堆砌，而是让每个环节都能继续推进的体验设计。

01

同图多轮迭代反馈

基于同一张图持续文字反馈，所有版本归档在同一条记录，直到点击「这一轮结束」。

02

切换模块不中断生成

生成任务由全局状态接管，切换功能模块后回到原页面仍可查看最新进度。

03

全局光标光晕

鼠标移动时跟随的柔和渐变光晕，为明亮界面增加一层微妙的沉浸感。

04

本地 SQLite 持久化

历程、版本和顾问会话全部落盘本地 SQLite，刷新页面后仍可恢复未结束的生成轮次。

09 / DEMO

演示流程

四步即可在现场完整演示从需求到归档的创作闭环。

STEP 01

登录本地 Demo

使用本地演示账号登录，JWT Cookie 保持会话状态。

STEP 02

上传商品参考图

选择 1-4 张商品实拍图，输入场景描述或让 AI 顾问辅助梳理。

STEP 03

生成与迭代

获取多版场景图，基于同一张图继续文字反馈，直到满意。

STEP 04

归档与下载

历程看板自动记录生成历史，支持筛选、搜索和批量下载。
